# 验证记录

## 验证原则

验证分两层：

1. **离线自动化测试**：通过 mock 构造模型响应，稳定覆盖消息配对、异常回灌和终止分支，不消耗 API。
2. **人工模型用例**：观察真实模型能否自主组织多步调用；结果用于演示，不作为确定性准确率指标。

## 自动化测试范围

| 模块 | 覆盖点 |
|---|---|
| `context.py` | system 保留、回合完整、消息顺序、超过条数预算的边界 |
| `tools_core.py` | 正常分发、未知工具、非法参数、非法表达式、文件与目录错误 |
| `react_loop.py` | 正常结束、输出截断、工具异常回灌、最大轮数兜底 |
| `graph_agent.py` | 条件边、消息 reducer、图执行上限 |
| `mcp_agent.py` | MCP schema 转换、正常结果、`is_error` 与调用异常回灌 |

运行：

```bash
pip install -r requirements-dev.txt
ruff check .
pytest
```

测试不读取 `.env`，也不会请求 DeepSeek。

2026-11-02 本地结果：**31 项测试通过**，Ruff 静态检查与格式检查通过。另行运行 `python mcp_client.py`，本地 MCP Server 成功返回 5 个工具，正常调用与预期错误路径均符合协议。

## 人工用例

以下用例在 2026-10-26 的 Python 3.12 环境中进行过手工验证。模型输出会随模型版本和服务端行为变化，复验时应关注调用路径而非逐字答案。

| 用例 | 输入 | 观察点 |
|---|---|---|
| 多步任务 | 查一下西安天气，然后算一下 `25*4+10` | 工具结果回灌后，模型汇总天气与计算结果 |
| 错误恢复 | 读取 `not_exist.txt` | 文件错误作为 tool 消息回灌，Agent 不崩溃 |
| 单步任务 | 现在几点了？ | 调用时间工具后结束，不进入无意义的额外循环 |
| 轮数上限 | 设置 `max_steps=1`，提出需要多步的问题 | 返回兜底文案，不无限运行 |

## 已验证的关键边界

### 按条数裁剪会破坏消息配对

固定条数裁剪可能留下 tool 消息，却删掉它对应的 `assistant(tool_calls)`。按回合裁剪后，同一组消息不会被拆开；自动化测试覆盖该不变量。

### LangGraph 的额度不是业务轮数

一轮 `agent → tools` 消耗两个 superstep。若把 `recursion_limit` 错写为 `max_steps + 1`，简单用例仍可能通过，但多轮任务会提前触发上限。

### stdio 不能被日志污染

MCP stdio 模式中，stdout 是 JSON-RPC 通道。Server 日志必须写入 stderr，否则客户端可能无法解析协议消息。

### MCP 工具可以独立扩展

本地 Server 从四个工具增加到五个工具时，Agent 通过 `list_tools()` 自动发现 `list_dir`，无需修改 Agent 循环或手写 schema。

接入官方 filesystem Server 后，同一个 Agent 可以获得目录列表等额外能力。这个对照说明的是**工具边界变化**，不是模型能力突然提升。
